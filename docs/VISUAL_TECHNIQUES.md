# Rendering and asset research

This release keeps a bright, stylized underwater town and adds believable surface detail and signs of daily activity. It retains the reduced coral/kelp density and the faster wagon speed.

## Techniques implemented

| Technique | Application | Reason |
|---|---|---|
| Shared color and tangent-space normal maps | Seven 512×512 families: wood, stone, metal, bun, rubber, cloth, sand | Surface relief responds to light without adding mesh polygons. |
| Correct color spaces | sRGB for surface colors; NoColorSpace for normals | Prevents lighting vectors from being treated as display colors. |
| Phong surface shading | Smooth hero models, textured props, seafloor | Provides per-pixel shading and specular highlights with a lighter model than the full physical material. |
| World coordinates for fine terrain detail | Repeated sand grain and normal maps | Keeps texture scale continuous as terrain chunks stream and change detail level. |
| Shared animated light uniform | Subtle moving water-light patterns on textured materials | Adds underwater motion in the material pass. |
| Contact shading and corner-supported foundations | Buildings, town furnishings, wagon | Anchors silhouettes to terrain and makes the wagon's height easier to judge during jumps. |
| Geometry merged by material | Landmark meshes and new static props | Repeated components use fewer draw batches. |
| Authored activity pockets | Fourteen sites across seven districts | Activity fits the purpose of each place: laundry and post near homes, markets and patios near restaurants, crates/rope and repair equipment near the cove. |

Textures are generated from deterministic, repeatable surface fields. They share memory across color variants and include mipmaps and anisotropic filtering. There are no additional runtime CDN requests. Existing terrain/scenery instancing and landmark LOD remain in use.

## Primary documentation consulted

- [Three.js materials](https://threejs.org/manual/pages/materials.html): shading models, specular highlights, relative rendering costs.
- [MeshPhongMaterial](https://threejs.org/docs/pages/MeshPhongMaterial.html): normal maps, shininess, texture color-space requirements.
- [Color management](https://threejs.org/manual/pages/color-management.html): color textures versus non-color data.
- [Texture](https://threejs.org/docs/pages/Texture.html): repeat wrapping, mipmap filtering, and anisotropy.
- [InstancedMesh](https://threejs.org/docs/pages/InstancedMesh.html): reducing draw calls through repeated geometry.
- [LOD](https://threejs.org/docs/pages/LOD.html): selecting simpler geometry with distance.

The performance choices are project-specific judgments based on this documentation. Target-phone frame rates must be measured on the real device.

## Verification

The unit suite checks terrain continuity, driving, ramps, saves, streaming disposal, clear roads, texture color spaces and normalized normals, grounded activity sites, reachable crowns, and a single stable landing after the floatier flight. The upgraded surface and terrain shader sources were generated by the installed Three.js WebGLProgram and compiled/linked on a Mesa llvmpipe graphics context. Build output is committed with source and uses relative asset paths for GitHub Pages.

SVG compatibility mode can show models and placement, but cannot show the WebGL normal maps or material shader effects. A compatibility screenshot verifies layout, not the final GPU surface detail.
